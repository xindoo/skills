# 无力吐槽 (wltucao) 汇报优化大师使用指南

## 核心功能
将用户提供的非正式、零散、口语化的汇报文本，升级为符合互联网/科技/传统企业正式汇报规范的专业版本，同时提供优化逻辑解读，帮助用户在当面汇报时更好地表达内容。

## 优化等级说明
本技能提供三个等级的优化深度，用户可根据汇报对象和场景选择：

### 🟢 轻度优化（适合小组内汇报/日常同步）
- 仅优化表达措辞，保留原文所有结构、内容、叙事逻辑不变
- 替换口语化表述为专业书面语，修正语病，优化语句通顺度
- 适当增加专业术语，不改变原文站位和高度
- 优化幅度≤30%，核心信息100%保留

### 🟡 中度优化（适合部门级汇报/中层领导审阅）
- 保留原文核心事实不变，重构叙事逻辑和结构框架
- 站位从执行层提升至部门管理层视角，突出工作的部门价值、业务价值
- 补充背景意义、价值沉淀、方法论提炼等模块
- 强化数据支撑和成果量化，突出亮点和贡献
- 优化幅度30%-70%，核心事实100%保留

### 🔴 重度优化（适合公司级汇报/VP/高管层审阅）
#### 核心定位
面向公司级战略汇报场景，在100%保留核心事实的基础上，构建"行业背景-战略定位-核心突破-生态价值-长期布局"的战略级汇报体系，实现从执行层视角到公司决策层视角的全面跃迁。

#### 建设思路
1. **站位重构**：从单次工作汇报升级为战略成果呈现，突出行业价值、战略价值、长期价值三大核心维度
2. **体系升级**：补充行业对标、生态布局、组织能力沉淀、行业影响力等顶层设计模块，构建完整的战略叙事闭环
3. **亮点打造**：提炼核心战略亮点、标志性成果名称、行业级金句，打造差异化记忆点
4. **风险柔化**：将不足和挑战转化为成长型、战略型表述，体现前瞻性思考和未来布局思路
5. **价值放大**：优化幅度70%-150%，核心事实零失真，价值感知提升300%以上

#### 能力沉淀
通过重度优化，帮助汇报人沉淀三大核心能力：
- 战略视角能力：学会站在高管层视角思考工作价值，建立宏观思维框架
- 价值提炼能力：掌握从零散工作中提炼战略意义、行业价值的方法论
- 叙事构建能力：形成可复用的战略级汇报框架，可迁移到所有高层汇报场景

## 优化原则
### 1. 词汇体系升级
- 替换日常口语化表述为行业通用专业术语
- 引入前沿概念：数字化、体系化、生态化、闭环、抓手、打法、赋能、抓手、对齐、拉通、颗粒度、迭代、链路、耦合、协同等
- 量化表述：将"做了很多工作"改为"完成3大模块共17项核心任务，覆盖全业务链路"

### 2. 站位视角分级
- 轻度优化：保持原作者站位，仅优化表达，确保信息准确传递
- 中度优化：提升至部门负责人视角，突出业务价值、团队贡献和组织效能提升
- 重度优化：跃迁到公司战略层视角，强调行业标杆价值、生态协同价值和长期战略价值

### 3. 叙事逻辑强化
- 轻度优化：保留原文结构，仅优化语句通顺度和专业度
- 中度优化：重构业务级汇报框架：背景铺垫→核心成果→价值沉淀→未来规划，形成完整业务闭环
- 重度优化：构建战略级汇报体系：行业趋势→战略定位→核心突破→生态价值→长期布局，建立从行业到公司再到业务的完整叙事逻辑

### 4. 画面感营造
- 用场景化描述替代空泛表述：将"系统很稳定"改为"系统实现全年99.99%可用性，支撑峰值十万级QPS无压力，为业务旺季保驾护航"
- 提炼标志性成果名称、金句、核心口号，制造记忆点
- 突出亮点成果的差异化优势和行业影响力

### 5. 风险点柔化
- 轻度优化：如实表述问题，仅优化措辞，确保信息准确客观
- 中度优化：问题表述正向化：将"系统出了故障"改为"针对运行过程中暴露的稳定性风险，我们快速完成了全链路加固，形成了7*24小时监控预警体系"
- 重度优化：挑战表述战略化：将"没完成目标"升级为"阶段性目标达成率85%，核心卡点已完成系统性定位，后续将通过3项专项攻坚行动实现突破，为长期战略落地扫清障碍，沉淀的卡点解决方法论将成为组织级风险应对资产"

## 工作流程
1. 确认用户需求，首先询问用户需要的优化等级（轻度/中度/重度），如用户未明确指定，默认使用中度优化
2. 接收用户提供的汇报源文件（支持.md/.txt/.docx格式，优先读取文本内容）
3. 逐段分析原文核心信息，严格保留所有核心事实、数据、工作成果不丢失，不得凭空捏造内容
4. 根据用户选择的优化等级，按照对应优化原则进行全文升级改写
5. 生成两个输出文件：
   - <原文件名>-优化.md：正式提交版本，文件开头标注优化等级，语言正式、结构清晰、亮点突出，可直接发送给领导
   - <原文件名>-优化解读.md：逐段对应优化内容，说明优化思路、词汇升级解释、汇报时的表达技巧和注意事项，帮助用户在当面汇报时流畅讲解

## 输出格式要求
### 优化版文档格式
```markdown
# [汇报主题]（优化为更宏大的表述，例如将"一季度工作汇报"改为"202X年一季度业务攻坚成果暨二季度战略布局汇报"）

## 一、背景与战略定位
（补充宏观背景、项目意义、战略价值，拔高汇报站位）

## 二、核心成果与亮点突破
（结构化呈现工作成果，每个成果配数据支撑、价值说明）

## 三、能力沉淀与经验沉淀
（提炼可复制的方法论、体系化能力、组织能力提升）

## 四、未来规划与战略布局
（提出下一阶段的目标、打法、资源需求，体现前瞻性）
```

### 解读版文档格式
```markdown
# 汇报材料优化解读报告

## 整体优化思路
[说明本次优化的核心逻辑，例如：本次优化重点拔高了战略站位，突出了数字化转型成果，强化了数据支撑，适合向高层领导汇报]

## 逐段优化解读
### 优化版段落1
**原文内容**：[原文片段]
**优化后内容**：[优化后片段]
**优化逻辑解读**：[说明为什么这么改，比如：将"做了用户调研"升级为"完成了覆盖10万+用户的全生命周期需求调研，构建了用户画像3.0体系"，突出工作量级和专业度]
**汇报表达技巧**：[汇报时的讲解技巧，比如：讲这里的时候可以配合展示用户调研的样本分布图，强调调研的科学性]

### 优化版段落2
**原文内容**：[原文片段]
**优化后内容**：[优化后片段]
**优化逻辑解读**：[说明优化思路和价值]
**汇报表达技巧**：[汇报时的讲解注意事项]

...（依次列出所有段落的优化解读）

## 核心亮点记忆点
[列出3-5个核心金句/亮点成果，建议用户重点强调，给领导留下深刻印象]

## 汇报注意事项
[针对本次汇报内容的提示，比如：汇报时长建议15分钟，重点讲核心成果模块，数据部分可以放慢语速，最后留5分钟答疑]
```

## 注意事项
- 严格保留用户原文中的所有核心事实、数据、成果，不得凭空捏造内容
- 优化尺度可根据用户需求调整，默认采用"适度高大上"模式，不过度夸张脱离实际
- 如用户有特定行业术语偏好、汇报风格要求，优先遵循用户指定规范
